# 05 --- Architecture Decision Records (ADR)

## ADR-001：保留 Java，不进行语言重写

**状态：已接受**

### 背景

当前问题集中在构建、模块化和运行时架构；尚无基准数据证明 Java
是压测瓶颈。

### 决策

保留 Java，优先现代化工程和运行时架构。

### 原因

-   最大程度复用已有业务逻辑和适配器；
-   降低协议语义迁移风险；
-   把改动集中在可验证的技术债上。

### 后果

仍需处理旧依赖、JDK 兼容和 Java 运行时成本。不能承诺仅靠移除 OSGi
就提升压测性能。

------------------------------------------------------------------------

## ADR-002：以 Maven 多模块作为目标构建系统

**状态：Tycho 作为现有 Bundle 的构建候选已验证；扩大迁移范围仍需单独评审**

### 背景

现有文档要求通过 Eclipse PDE 导出插件，发行包由脚本装配。

### 决策

采用 Tycho 1.7.0/JDK 8 构建当前 30 个非 Manta Bundle，并沿用现有发行打包脚本。当前验证确认 Tycho 可以生成对应 Bundle 并组成用户手动验证可用的发行包；不据此移除 OSGi、改变运行架构或迁移 Manta。Manta 继续独立处理。详细操作和产物差异见 `09-tycho-build-and-package.md`。

### 原因

-   无 IDE 交互构建；
-   CI 易集成；
-   模块依赖和版本可追踪；
-   测试与打包进入标准生命周期。

### 后果

Tycho 1.7.0/JDK 8 带来旧版本生命周期风险，当前接受该风险。构建成功不代表 OSGi 运行时已经移除，也不代表 Tycho JAR 与 Eclipse JAR 字节相同；任何扩大构建范围或替换发行架构的工作仍需独立审阅。

------------------------------------------------------------------------

## ADR-003：逐步移除 OSGi，而不是直接删除文件

**状态：提议；替换运行时需单独设计审阅与用户授权**

### 背景

OSGi
提供类加载隔离、服务注册和生命周期。其必要性取决于源码实际使用方式。

### 决策

先清点所有 OSGi 能力使用点，再替换为普通 Java
入口、显式注入、生命周期管理和适配器 SPI。

### 原因

若不需要运行时热插拔，标准 Java
方案通常更简单；但必须先证明动态模块能力不是关键功能。

### 后果

如果适配器确实依赖动态类加载或版本隔离，需设计插件 ClassLoader
或重新评估保留部分插件框架的价值。

------------------------------------------------------------------------

## ADR-004：先不强制启用 JPMS

**状态：暂定；依赖结构稳定后复核**

### 决策

初期优先普通类路径；当前 Tycho 构建可保留现有 Bundle。待依赖结构稳定后，再评估 JPMS。

### 原因

避免在一次迁移中同时处理旧依赖、反射访问和模块路径限制。

### 后果

模块可见性主要通过工程结构、包设计和测试约束；后续可以再加强。

------------------------------------------------------------------------

## ADR-005：保留 Controller/Driver 进程边界

**状态：已接受，除非审计证明需调整**

### 决策

不因现代化而拆成更多微服务。

### 原因

原系统已经具备控制与执行分离。新增服务会增加 RPC、部署和故障处理复杂度。

### 后果

仍需维护 Controller 与 Driver 的通信协议和版本兼容。

------------------------------------------------------------------------

## ADR-006：适配器优先采用启动时发现

**状态：有条件接受**

### 决策

若适配器只在进程启动时装载，优先采用 Java SPI
或显式注册；不默认支持热插拔。

### 原因

比完整 OSGi 动态服务生命周期更简单。

### 后果

不再自动获得 Bundle
动态更新、隔离和服务上下线能力。若这些是硬需求，需要另行设计。

------------------------------------------------------------------------

## ADR-007：分离 OSGi 移除、JDK 升级与性能优化

**状态：已接受**

### 决策

三个变更分别实施和验收。

### 原因

便于定位兼容性问题和衡量性能变化。

### 后果

阶段数较多，但风险更可控。
