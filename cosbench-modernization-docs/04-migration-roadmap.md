# 04 --- 分阶段迁移路线图

## 总原则

每个阶段必须有独立交付物、测试证据和回退点。未完成阶段验收，不自动进入下一阶段。

## Phase 0 --- 静态源码审计

**状态：源码与配置审计报告已生成。** 当时审计不包含构建 PoC；之后完成的 Tycho 构建与发行打包见下节和 `09-tycho-build-and-package.md`。Phase 1B 和 Phase 2 状态以用户报告的手工测试通过为准；静态审计本身不作为运行验收证据。

## Tycho 构建与发行包（当前收窄目标已完成）

Tycho 1.7.0/JDK 8 已在隔离副本中构建 30 个 Bundle、导出到 `dist/osgi/plugins` 并通过 `pack-sineio.sh` 生成 tar.gz。30 个 Bundle 文件名与 `cosbench-modernization-docs/旧包/plugins` 中的 Eclipse JAR 对应。Tycho 与旧 Eclipse JAR 并非字节级相同；用户已手工解包并报告程序可用。操作、证据文件和已知差异见 `09-tycho-build-and-package.md`。

## Phase 1B --- 发行包与运行路径基线

**状态：已完成（用户报告手工测试通过）。** 测试用例、日志和结果明细尚未归档在本目录中；历史测试范围见 `08-phase0-review-phase1-plan.md`。

## Phase 2 --- 测试护栏

**状态：已完成（用户报告手工测试通过）。** Phase 2 的目标范围如下；具体手工测试记录尚未归档在本目录中。

-   配置解析和 workload 模型；
-   适配器契约与核心操作；
-   错误、超时、重试和关闭行为；
-   统计语义和结果格式；
-   小对象高并发和大对象吞吐场景。

## Phase 3 --- Tycho 多模块构建收口

**状态：已完成（2026-10-21）。** 固定 digest 的 Docker 干净构建成功，30 个非 Manta Bundle 均生成；旧 Eclipse 基线 30/30 文件名对应，MANIFEST 关键头和 Bundle-ClassPath 一致，归档资源未发现丢失。Manta 仍在 Tycho reactor 之外。完整命令、环境和差异见 [`10-phase3-tycho-closeout.md`](10-phase3-tycho-closeout.md)。本阶段没有修改 POM、源码、CI 或运行路径；既有打包及用户手工可用性证据继续适用。

### 任务

-   审阅现有根 POM、模块 POM、Bundle 依赖图和 Phase 1A 结果，记录已满足与未满足的验收项。
-   仅在证据不足或存在缺口时，核实 Tycho target platform/P2 依赖来源、版本管理和校验方式，以及 Bundle/fragment/嵌入式 Bundle-ClassPath、资源和 MANIFEST 保留情况。
-   仅补齐未覆盖的 Maven/Tycho 生命周期、模块依赖或构建可重复性问题；不重复创建 parent POM。
-   若已有打包证据不能覆盖后续改动，则在隔离副本中验证产物导出到 `dist/osgi/plugins` 和 `pack-sineio.sh` 发行包组装。
-   保持 Manta 独立，并保持 Equinox、Spring OSGi、Controller/Driver 运行方式和业务语义不变。

### 验收

-   每项标准均由 Phase 1A 现有证据或新增的固定 digest Docker 验证覆盖；没有未解释的空项；
-   依赖来源和版本可追踪，Manta 边界明确；
-   Bundle 清单、MANIFEST、Bundle-ClassPath 和资源检查无未解释的遗漏；
-   若修改了构建或打包内容，隔离构建及发行包 smoke test 通过；否则复用已有 Phase 1A/1B 证据并说明适用范围。

## Phase 4 --- 替换 OSGi 运行时

**状态：下一项路线图任务，未开始；必须经审阅并获得单独授权后方可开始。** Phase 3 收口不构成 Phase 4 授权。此阶段将改变运行时架构，须先逐项设计 OSGi 服务发现、组件装配、生命周期和类加载边界的替代方案，再按本节验收标准实施。

### 任务

-   [ ] 为 Controller 建立标准 Java 入口和生命周期。
-   [ ] 为 Driver 建立标准 Java 入口和生命周期。
-   [ ] 将 Bundle 启动依赖转为显式装配。
-   [ ] 替换 OSGi 服务发现。
-   [ ] 评估适配器使用 Java SPI 或显式注册。
-   [ ] 处理资源关闭和在途任务。
-   [ ] 移除运行路径中的 Equinox/Spring OSGi 依赖。
-   [ ] 清理不再需要的 `config.ini` 启动级别配置。
-   [ ] 维持外部 API、workload 配置和结果格式兼容。
-   [ ] 在独立分支/提交中完成并运行全量回归。

### 验收

-   Controller/Driver 不依赖 OSGi Framework 启动；
-   所有支持的适配器和操作有测试证据；
-   生命周期关闭行为可靠；
-   无遗漏的 Bundle API 引用；
-   发行包中没有运行时必需的 OSGi 依赖（如仍有遗留文件，必须解释原因）；
-   与原版行为可比。

## Phase 5 --- JDK 与第三方依赖升级

**状态：未开始；Phase 4 通过审阅且获得单独授权后方可开始。** Java 21 仍只是候选目标，不是已验证兼容承诺。

### 任务

-   [ ] 确认 Java 21 兼容性清单。
-   [ ] 升级/替换不兼容 SDK 和库。
-   [ ] 检查 TLS、反射、序列化、XML 和日志行为。
-   [ ] 运行全量测试。
-   [ ] 记录安全与许可证变化。
-   [ ] 对比旧/新 JDK 的资源与性能指标。

### 验收

-   新 JDK 下功能回归通过；
-   关键依赖有明确版本与许可证；
-   性能变化有测量数据；
-   升级可以独立回退。

## Phase 6 --- 压测引擎优化

**状态：未开始；架构稳定、性能基线可复现且获得单独授权后方可开始。**

### 任务

-   [ ] 分析 CPU、GC、线程、连接池、统计和网络瓶颈。
-   [ ] 只优化有数据证明的热点。
-   [ ] 评估连接复用、缓冲区、统计聚合、背压和虚拟线程。
-   [ ] 运行基准测试，防止测试语义变化。
-   [ ] 建立性能回归阈值。

### 验收

-   任何性能改进都能复现；
-   不以减少实际数据量或漏统计请求换取指标；
-   功能和统计语义保持一致；
-   有性能对比报告。

## 回退原则

-   每个 Phase 单独分支或小步提交；
-   保留最后一个已知可用发行包；
-   不删除旧启动方式，直到新方式通过验收；
-   回退时只回退本阶段提交，不重置用户其他改动；
-   数据格式/配置迁移若不可逆，必须提供备份和兼容策略。
